# Arcana mobile-first UX audit • 2026-10-16

## Scope and method

Reviewed the current production branch `release/arcana-mobile-2026-10-15`, recent user-supplied Android screenshots of Pathfinder and its grouped materials, appearance management, page-layout CSS, account navigation, Wiki, community, Pathfinder, and shared routing. Static source inspection and automated build tests were used. This is **not** a claim of a device-by-device browser walkthrough; real Samsung Internet, Chrome, Firefox, iOS Safari, and screen-reader verification remains necessary.

## Fixes implemented in this pass

| Area | Finding | Remediation |
| --- | --- | --- |
| Mobile viewport | A narrow page could scale below readable size, with blank space beside content. | Added `minimum-scale=1` while leaving zoom-in enabled; constrained root and content overflow without suppressing deliberately scrollable child rails. |
| Mobile controls | Small input text and stacked enhancement selectors made the From → To screen longer than necessary. | Raised narrow-screen input sizes, restored 2-column rank/enhancement fields inside each From/To row, tightened section rhythm, preserved native accessible selects. |
| Mobile navigation | Translucent fixed navigation could let page copy show through at scroll positions. | Use opaque theme-colored top bar and bottom dock while preserving theming. |
| Upgrade materials | Every biome expanded immediately, making a 15-19-material list overwhelming. | Biomes are individually collapsible, the first section opens by default, labels and material rows have a clearer visual hierarchy. |
| Recipe data provenance | Some material sources display ambiguous `Tier 0` metadata. | Do not present zero as a meaningful biome tier; leave absent/unverified tiers unclaimed. Never invent source biomes. |
| Global appearance | Several extra typography, button, density, and panel styles were gated on the admin role, instead of the presence of an active published theme. | Use an explicit `data-arcana-design-active` state for published visitor styling and private appearance preview. |
| Theme variety | Six presets and seven patterns were too limiting; some patterns did not appear in the miniature preview. | Expanded to 18 themes and 18 CSS-generated texture modes with matching mini preview, searchable preset names and selected-state indicators. |
| Accessibility | Inconsistent keyboard outline and narrow-screen select sizes. | Added visible focus outlines, sensible mobile tap targets and font-size floor for controls. No `user-scalable=no` or `maximum-scale=1`. |

## Source-based functional audit

- **Home / navigation:** Keep two central homes for discovery: the main home and contextual navigation. Header search, dock, routes, and page source patterns reviewed for narrow-screen containment. Preserve user-selected subpage paths.
- **Pathfinder:** From → To vs quick Upgrade Map remains a legitimate distinction, but the older “Upgrade Costs” reference uses a *partial* tier-only data view. This should eventually be merged/renamed after the verified cost source and routing are audited rather than silently promoted as full cost data.
- **Build Studio / runes / passives:** Keep saved build state, share links, and allocation logic separate from appearance-only updates. No game values or data files altered.
- **Wiki / Codex:** Preserve images and article crosslinks. Do not infer game mechanics, biome unlock orders or material rates from the UI. Test long headings, mixed-length lists and page-level anchors on mobile.
- **Profiles / private checklists:** Saved farming lists are account-owned and must not appear in public profile reads. Do not alter account authorization or remove durable volume.
- **Admin:** Only Creator/Admin can preview and publish one global theme; guests see the published design without edit tools. New presets do not automatically publish.
- **Beta feedback, guild and raid pages:** Retain working navigation, forms, and reporting links; no behavioral overhaul without cross-device QA.
- **Desktop native selects:** The earlier explicit dark popup/background correction remains intact.

## Remaining hands-on acceptance checks

1. Samsung Internet at ordinary system text sizing: open Pathfinder Map, From → To, long biome list, expand/collapse categories, save and check off materials. Confirm width fills screen at normal zoom, and pinch zoom **in** still works.
2. Chrome desktop at common widths: 320, 375, 430, 768, 1024, 1440px; check native select contrast, nav, forms, modal positioning, and horizontal rails.
3. Appearance Studio in admin login: search presets, test all background textures and the mini preview, publish one theme, verify guest view, then rollback. Confirm no visitor-specific theme overrides.
4. Wiki: article creation/editing/upload, headings, table overflow, Codex category navigation and last scroll restoration.
5. Build Studio: gear modal, rarity/awaken controls, rune placement, passive Free Allocation, saving to account, and return-to-work.
6. Community: public profile privacy, private checklists, guild/LFG forms, error states and keyboard navigation.
7. Evaluate whether the legacy partial `Upgrade Costs` and `Compare Items` modes belong inside Pathfinder's primary navigation or as context actions elsewhere.

## Safety

No changes to upgrade recipes, game values, user accounts, guild records, persistent volume, or published Wiki articles. Changing the public theme still requires an explicit admin publish. Verify production health after the last build and perform hands-on device testing before marking the entire UX audit complete.
