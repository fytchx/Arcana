# Pathfinder ML XP, one-shot planner (185–500)

## Scope and purpose

Players select **Monster Level (ML) 185–500** and their farming biome. Pathfinder shows estimated Monster Level XP required to reach the next level, plus estimated full-level **XP-awarding kills** for weakest (−10%), regular and strongest (+10%) monsters. No kill speed, damage or manual XP input is requested. Each scenario also displays an **ideal ETA** assuming exactly one normal XP-awarding kill per second without interruptions.

This is **screenshot-calibrated research**, not datamined server leveling code. Keep the UI's approximately/equivalent markers visible. For this intentionally simple view, the selected progression ML **is also assumed to be the farming ML**, a meaningful simplifying assumption that users need to understand. One-shot kills mean one kill per monster. The ETA is deliberately separate: a **1 XP-awarding kill/second optimistic benchmark**, not a measured farming rate or guarantee.

## Source and formula

The regression source is the archived screenshot set documented in the October 28 ML XP research notes on the branch `preview/season2-complete-guide-2026-10-27` and `MLxp.zip`. Of 36 screenshots supplied, 33 are distinct.

The estimated ML XP requirement uses the bounded empirical degree-six fit:

```
z = (ML-300)/100
XP_to_next = round(
  598801.760018 + 631551.611753*z + 202096.479878*z²
  -3048.16010589*z³ -10654.7857437*z⁴
  +58.3786439647*z⁵ +412.03319736*z⁶
)
```

This formula is strictly limited to ML 185–500. The sampled requirement data includes 210 (189.52K), 290 (537.67K), 332 (821.38K), 400 (1.42M), 420 (1.62M) and 482 (2.3M). The UI labels values as approximate because these observations are rounded and unobserved levels are interpolations.

Biome-card XP/kill is modeled as:

```
base_card_xp = round2(biome_base * (1 + (fighting_ML-280)/400))
position_xp = round2(base_card_xp * position_modifier)
kills_to_level = ceil(XP_to_next / position_xp)
```

Position modifiers are 0.90, 1 and 1.10 from **Murky Depths onward**. The first two biomes do not have those modifiers, so the UI deliberately shows the same value for all three and explains why. The 12 biome bases are: Verdant 4, Scorched 6, Murky 8, Frozen 10, Shadow 14, Infernal 20, Elder 24, Glass 27, Drowned 30, Summit 33, Rift 36, Crown 39.6.

The result cards round kill estimates to the nearest ten for clarity and prefix them with ≈. ETA is calculated from unrounded modeled kills and is rounded up to whole minutes. Internal calculation uses the unrounded estimated XP requirement and two-decimal estimated XP/kill.

## Player-facing assumptions

- The selected ML is the player's current ML **and** the fighting ML.
- The player one-shots their selected monsters.
- One normal kill grants the modeled Monster Level XP; Extra Kill/Frenzy, specialized multipliers, interruptions and time-to-kill are **not** included.
- XP required represents a fresh level (zero progression in current ML). It is **not** remaining XP after any partly filled bar.
- ETA assumes one ML XP-awarding kill each second, no downtime, no deaths, no failed one-shots and no Frenzy kills. The older wiki documents the default one-attack-per-second cadence, but the client does not prove every actual attack yields a qualifying kill; label ETA **ideal**.
- Only **standard biomes** in the calibrated biome list are offered. The Elemental Conflux and the Convergence have their own behavior, so their XP is not projected using a standard biome base.
- Standard biome unlock MLs are sourced from the live `/api/config/game`, version `2026-10-28-005`: Verdant 0, Scorched 10, Murky 30, Frozen 45, Shadow 65, Infernal 90, Elder 115, Glass 150, Drowned 185, Summit 220, Rift 260, Crown 300.
- Locked biomes are disabled. If a player lowers ML below the saved biome's unlock requirement, Pathfinder automatically switches to the highest unlocked standard biome. The next unlock is displayed.
- No claim of sub-ML-185 accuracy or server-extracted exactness.
- The user's last selected ML/biome is stored in localStorage, independently from Pathfinder's materials and other calculators.

The October 28 follow-up adds verified biome requirements and per-scenario optimistic ETAs without any new input controls.

The tool is found at `/#/calculators/pathfinder?view=ml` (exact hash/query form may vary with the router). There is **no separate site route** for the tool.

Do not silently replace the empirical research model with an unverified formula, even if a later APK or patch note mentions a new XP mechanic.

## October 29 journey planner update

The primary ML XP interaction is **Current ML → Target ML**, not a single-level calculator. The default journey is ten Monster Levels, with a simple target-jump row (+1, +5, +10, +25, +50, ML 500). Target ML is **exclusive**: ML 332 → 333 includes the cost of progressing through ML 332, not ML 333.

The two secondary controls live in closed disclosure panels by default:

1. **Current level progress**, an optional percentage slider from 0 to 99. When set to 50%, the current level's remaining XP is half; every subsequent level retains its full XP requirement. This is starting progress, not character level.
2. **Farming settings**, with default Auto biome progression and optional fixed farming biome. Auto selects the highest **currently unlocked standard biome at each progression ML**. Fixed uses the selected already-unlocked biome for every step. Auto assumes the player can one-shot the newly unlocked monsters; the fixed option exists precisely for players who cannot.

Math: for each progress ML `m` in `[current,target)`, use `requiredMlXp(m)` and the fight-ML-`m` biome-card XP model. Apply the progress fraction only to `m=current`, then round that step's remaining requirement up to whole XP. Compute qualifying kills as `ceil(needed_m / XP_per_kill_m)` separately for each ML and each monster-position scenario; sum those **whole per-level kill counts** and derive ideal ETA at 1 qualifying kill/s. Never multiply one level's kill count by the number of levels.

The user-facing hero highlights the **Regular** scenario's total ideal ETA, total XP and total kills. Three compact cards retain Weakest/Regular/Strongest estimates. Exact game-server XP and real farming times remain **unverified**; display approximation marks and brief assumptions. Data is clamped to 185–500 and the target cannot precede the current ML. At current=target, display zero XP, zero kills, zero ETA.

Existing local save `arcana-pathfinder-ml-xp-v1` is migrated by defaulting any missing target to current+10, missing progress to 0, and missing farm mode to Auto while retaining a valid saved biome. Persist all fields.

The main UI must have **no kill-speed input**, no forced progress slider, and no sprawling 316-point table. Regression coverage now includes A-to-B totals, zone boundaries at 220/260/300, optional progress and the phone-sized browser.

## October 30: Extended, explicitly estimated ML 1–500 coverage

**Player request:** Include new characters without pretending we have verified all 500 requirements. The existing ML 185–500 screenshot-calibrated formula and each standard biome's verified unlock level are preserved unchanged.

**User-supplied new-character reports (October 29):**
- Early exact-looking reports: ML 2=78, ML 4=140 (outlier vs linear ML 4=130, retain reported value), ML 5=156, 6=182, 7=208, 8=234, 9=260, 10=400, 11=437, 12=473, 13=510, 14=546, 15=584, 16=626, 17=671, 18=720, 19=771, 21=886, 22=949.
- Rounded displays reported: ML 23=1.01K, 24=1.08K, 25=1.16K, 26=1.24K, 27=1.31K, 28=1.40K, 29=1.49K, 30=2.25K, **42=4.2K**. These are approximate observations, not single-XP-precision ground truth. ML 184=124.49K is from prior player screenshot calibration.
- Not observed: ML 1, ML 3, ML 20, and most ML 31–183.

**Bounded XP requirement method:** Prioritize direct reports at their exact ML. For other early levels, use:
- ML 1–9: `round(26*(ML+1))` (except observed ML 4=140).
- ML 10–14: `round(26*(ML+1)*1.4)` (all five levels verified against reports).
- ML 15–29: `round(585 + 39*(ML-15) + 1.82*(ML-15)^2)`. Known reported levels override this approximate fit.
- ML 30–184: Positive, monotonic offset power interpolation `round(0.04708457816641641*(ML+17.794012648560958)^2.786338983223726)`, anchored at approximately ML 30=2,250, ML 42=4,200, ML 184=124,490. Reported ML 30 and 42 override calculated projections. **ML 43–183 has sparse evidence and very low confidence**. It must be marked provisional in the UI, not presented as the recovered server formula.
- ML 185–500: Keep the previously screenshot-calibrated high-level polynomial *unchanged*. At ML 184→185 the difference is small and positive; both domains are still estimates.

**Low ML biome XP-per-kill:** Screenshots of a new character at ML 10 and ML 30 show Verdant Woods **1.50 XP/kill**, Scorched Sands **2.25**, Murky Depths **3.00**. The old `base*(1+(fightingML-280)/400)` extrapolation predicts *less* at ML 10, so infer an **unverified floor at 0.375× biome base**: `round2(base*max(0.375,1+(ML-280)/400))`. Use this model over ML 1–500. It is a hypothesis backed by low-level card examples, not extracted game code; some players farm at a fighting ML different from progress ML.

**UI/accuracy:** Existing two-number ML journey, per-level kill rounding, optional starting progress, auto/fixed biomes and 1 qualifying kill/sec *ideal* ETA remain intact. A small but visible 'Early ML estimates' message appears for any selected route involving ML below 185, and explicitly warns if ML 43–183 is included. The old single-level estimates in ML 185–500 are not altered.

**Needed validation:** New screenshots of XP requirements around ML 43–65, ML 90, ML 115, ML 150 and of biome-card XP below ML 30 would reduce uncertainty considerably. Do not silently imply the interpolated stretch is verified by current game files.
